# The repo is a wiki whose links are generated from frontmatter, not hand-authored

The library is meant to be browsed like an encyclopedia — jump from an exercise to its harder variant, to the quality it trains, to a demo video — and to later power visualizations (a graph of progressions, a tag explorer). That needs links between files. The question was *what kind* of links and *who writes them*. We considered: (A) hand-authored links in each file's body; (B) Obsidian-style `[[wikilinks]]`; (C) relative markdown links generated from the frontmatter that already encodes the relationships. We chose **C**.

Frontmatter is already the structured source of truth — `progression`/`regression` slugs, `focus`/`equipment`/`level` tags. Links are a *projection* of that data, so authoring them by hand (A) duplicates the data and invites drift: a renamed file or retagged exercise silently rots its links. Generating them keeps one source of truth. We rejected `[[wikilinks]]` (B) because the primary reading surface is GitHub web, which renders relative `[Name](slug.md)` links as clickable but ignores `[[…]]`; wikilinks would also couple us to Obsidian. Relative markdown is GitHub-native today and trivially parseable by a future viz layer.

`scripts/build-wiki.py` is the single authority: it reads every exercise's frontmatter and regenerates a footer (Trains / Progressions & regressions / References) below a `<!-- wiki-footer -->` sentinel, rebuilds `exercises/README.md` as a focus-grouped index, and flags any `progression`/`regression` slug that points at a missing file. It is idempotent — authors (and `/add-exercise`) write only frontmatter + prose above the sentinel, then run the script. `sources`/`videos` frontmatter carry external references (videos are supplemental human material, never parsed — see [SPEC.md](../../SPEC.md)). Workouts link their exercises back to the library inline.

Consequence: correctness of navigation lives in frontmatter quality plus one generator, not in 23-plus hand-edited footers. Hand-maintained backlinks (vocabulary → exercises, the reverse graph) are deliberately out of scope: the same frontmatter that feeds the generator can feed a future visualization layer that derives them. If link maintenance ever needs to happen on write rather than on demand, the documented path is a commit hook that runs the existing script — not moving link text back into the files by hand.
